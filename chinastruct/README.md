# chinastruct：中文长文档结构提取层

建在 PageIndex 之外，不改动上游代码。它解决上游在中文版式上的结构性缺陷，
并附带一套语料入库校验与评测流程。与具体领域无关——指南、政策文件、法规、
报告用的是同一套版式与编号习惯。

## 为什么需要它

上游的正文提取能正确分开双栏，但标题检测走另一条线路，会把期刊的左右两栏
拼成一行，于是从拼接出的句子里"造"出标题。结果是这类文档只切出 5 到 12 个
节点、标题多为正文残句，同一套规则在不同版式上节点密度能差 19 倍。

本层先重建行、按行内空隙定位栏位再识别标题；编号体系（`一、`／`（一）`／
`1.`／`1.1`／`第X章`／`第X节`）按文档实际用法映射层级。

## 模块

| 文件 | 作用 |
|---|---|
| `lines.py` | 按字符坐标重建行、定位栏位并分栏、估算正文字号、识别图形页 |
| `build_tree.py` | 编号识别、标题判据、层级映射、树组装；有可用书签时优先用书签 |
| `gate.py` | 入库闸门：判断一份 PDF 是不是正常文本文档 |
| `gate_selftest.py` | 用合成文件验证闸门确实能拦住幻灯片与扫描件 |
| `fetch_guidelines.py` | 下载管线：检索 → 下载 → 校验 → 过闸 → 归档，并记录出处 |
| `evaluate.py` | 在语料上对比本层与上游原版的指标 |
| `compare.py` | 打印前后对比表 |
| `health_check.py` | 语料体检（页数、行数、字号、图形页、书签） |
| `diagnose.py` | 逐行打印分类结果，换新领域调规则时用 |
| `..\baseline\run_baseline.py` | 只跑上游原版，产出对比用的基线 |

## 与效力层的关系

这一层负责「把文档变成一棵树」；`..\haikou\` 负责「这棵树上的内容还算不算数」。
两者是前后相继的两段，通过 `haikou\force_layer.py` 对接，接入点有两个：

| 环节 | 调用 | 效果 |
|---|---|---|
| 建树之后（前置） | `ForceLayer.annotate(tree, 文档名)` | 每个节点带上 `force` 字段：状态、原因、已查范围、缺失证据、下一步建议 |
| 检索之后（后置） | `ForceLayer.review(hits, policy)` | 按 `flag`／`drop`／`strict` 过滤并生成警示 |

效力是文档级事实，所以节点继承所属文档的状态；节点自带该字段后，命中无需
再回查数据库。三态判定（现行有效／效力存疑／已废止）与两个废止来源
（废止通知、文件正文里的"同时废止"条款）详见 `..\haikou\README.md`。

`force` 字段不是状态词，而是一份说明：判定原因、已核查的范围、还缺哪条证据、
使用者下一步该做什么。特别是"效力存疑"——必须能回答"为什么存疑、缺什么、
怎么办"，否则只是一个没用的问号。

效力维度有两条落地路径：**文本语料的推理检索**（`haikou\reasoning_retrieval.py`，
模型读带效力的目录自行选条）与 **PDF 客户端适配**（`haikou\pageindex_force_adapter.py`，
把效力注入 `get_tree`／`get_ocr`／`get_document` 的返回）。两条路共用同一个
`ForceLayer`，也共用 `haikou\force_protocol.py` 这一份推理协议，所以判定与规则
都不会各说各话。主线分工见 `..\SPINE.md`，细节与注意事项见 `..\haikou\README.md`。

| 层 | 目录 | 输入 | 输出 |
|---|---|---|---|
| 结构层 | `chinastruct\` | PDF | 带标题层级的 PageIndex 树 |
| 效力层 | `haikou\` | 文档正文与目录 | 每个节点的效力状态与依据 |
| 检索层 | `haikou\retrieval.py` | 问题 | 带出处与效力标注的条文 |

## 入库四条规则

1. **有文字层**：每页可提取文字不少于 200 字符，否则视为扫描件
2. **不是图形页为主**：过半页面为大字图形页则拒绝（幻灯片、图解）
3. **书签是真实目录**：书签若为"幻灯片 N""Page N"这类导出占位则拒绝
4. **是正文文档**：每页行数不少于 6 行

规则只判断**格式**，判断不了**出处**。下载管线会额外记录来源 URL 与域名，
并标记非官方域名（非 `*.gov.cn`、`*.org.cn` 及已知期刊站），这类文件需人工
确认是否为权威原文——企业制作的"概要版"版式完全正常，只有出处能区分。

## 用法

```bash
# 语料体检（--park 把不合格的移入 _excluded 并记录原因）
python gate.py <语料目录>

# 验证闸门仍然有效
python gate_selftest.py

# 下载新批次（清单为 JSON：主题、文件名、检索词、必须出现的关键词）
python fetch_guidelines.py --targets batch.json --out <语料目录>

# 跑上游基线，再跑本层，然后对比
python ..\baseline\run_baseline.py
python evaluate.py
python compare.py
```

清单格式：

```json
[
  ["01-主题", "文件名", ["filetype:pdf 检索词"], ["必须出现的关键词"]]
]
```

下载结果分三类：`ok`（过闸入库）、`excluded`（过闸失败，移入 `_excluded`
并记录原因）、`failed`（没找到可用 PDF）。出处写在 `_provenance.json`。
下划线开头的目录会被闸门与评测脚本自动跳过。

## 换领域要改什么

**不用改**：分栏、行重建、字号估计、编号识别、闸门规则、下载管线、评测流程
都与领域无关。

**要重做**：目标清单、语料本身、评测集标注。

**要新增**（以政策法规为例）：

1. **网页入口**——政策文件多以网页而非 PDF 发布，需要抓正文转 PDF，或在
   管线里加一条 HTML 分支
2. **条文级索引**——法规的引用单位是"第X条"，不是章节。需要为每条生成可
   定位节点，否则"这条规定出自第几条"回答不了
3. **版本谱系**——同一政策常有多个年度版本，节点要带版本标识，用于新旧对照

## 已知不足

- 阿拉伯数字编号 `1 / 1.1 / 1.1.1` 的层级映射未做透，深文档可能只到二级
- 复杂表格区域的行重建仍会串行，可能产生噪声标题
- 目录页、图文混排页的标题识别偶有漏检
