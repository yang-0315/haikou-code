# haikou：政策文档的效力层

给 PageIndex 的树检索加上"这条规定还有效吗"这一层。对外只有两个接入点，
内部是一条数据流。

项目主线（spine）与两条后端的分工写在 `..\SPINE.md`：协议本体是
`force_protocol.py`，`reasoning_retrieval.py` 是主 demo，
`pageindex_force_adapter.py` 是可移植证明。推理规则只有那一份源。

结构提取本身由 `..\chinastruct\` 负责（PDF → 带标题层级的树）；本层只处理
「树上这条内容还算不算数」。两层通过本目录的 `force_layer.py` 对接，分工与
接入方式在 `..\chinastruct\README.md` 里也做了交叉说明。

## 数据流

```
抓取发现 ──→ 废止关系解析 ──→ 效力判定 ──→ ┬─ 前置：标注到树节点
（目录/正文）  （通知＋文件内条款）  （三态）    └─ 后置：审查检索结果
```

| 层 | 模块 | 作用 |
|---|---|---|
| 目录层 | `crawl_all_channels.py` | 遍历栏目录得全部文件元数据（1872 份） |
| 正文层 | `docstore.py` | 按需抓取正文并缓存；取用时顺带扫废止条款 |
| 关系层 | `repeal.py`、`embedded_repeals.py` | 废止通知解析 + 文件内"同时废止"条款 |
| 判定层 | `warn.py` | 三态判定：现行有效／效力存疑／已废止 |
| 条文效力 | `article_force.py`、`build_article_force_index.py` | 从修改决定识别“删去第X条”和款/项删除，生成条文级部分废止索引 |
| **接口层** | **`force_layer.py`** | **前置标注与后置审查的唯一入口** |
| 检索层 | `retrieval.py` | 条文级检索，警示与排版委托给接口层 |
| **协议层** | **`force_protocol.py`** | **引擎无关的效力推理协议：状态含义、选条／作答规则、输出契约（spine）** |
| 时点层 | `temporal.py` | 按公布日、明确施行日与废止生效日重算历史时点效力；证据不足时降为存疑 |
| 时点证据 | `temporal_evidence.py`、`build_temporal_index.py` | 全量提取日期来源、文件类型、精度与缺口，持久化为 `_temporal_index.json` |
| 模型 Provider | `llm_provider.py` | 统一 DeepSeek／OpenAI／OpenAI-compatible／本地模型接口、配置、重试与错误 |
| 路由层 | `retrieval_router.py` | 先判断问题该走哪条检索路（条号／单文档树／多文档／表格目录／语料外） |
| 事项目录 | `catalog_index.py` | 从官方 PDF 附件还原《执法事项指导目录》的事项—法律—条款结构 |
| 推理检索 | `reasoning_retrieval.py` | 模型读带效力的目录、自行选条并作答 |
| 树索引 | `tree_index.py` | 把正文切成 PageIndex 形状的树（章 → 条，按页计跨度），每个节点带 force；并充当客户端数据层 |
| 沿树检索 | `tree_retrieval.py` | 模型按 node_id 在树上选节点、按节点读正文——与 `reasoning_retrieval` 同一套协议，换的是寻址方式 |
| 客户端适配 | `pageindex_force_adapter.py` | 把效力注入 PageIndex 客户端的工具返回 |

## 两个接入点

### 前置：给树加效力标注

树建好之后立刻标注，之后无论谁读这棵树，每个节点都自带效力信息。

```python
from force_layer import ForceLayer

layer = ForceLayer(database)
annotated = layer.annotate(tree, "海南自由贸易港建设投资基金管理办法")
# 每个节点新增 force 字段：
# {"status": "系列已废止", "confidence": "medium",
#  "evidence": {...}, "caveats": [...]}
```

命令行：

```bash
python force_layer.py --tree tree.json --title "文档名" --out annotated.json
```

效力是文档级事实，所以节点继承所属文档的状态；节点自己带着它，命中之后
无需再回查数据库。

### 后置：审查检索结果

检索返回节点后，按策略过滤并给出警示。

```python
reviewed = layer.review(hits, policy="flag")
# reviewed["kept"]      通过审查的命中（已附 force）
# reviewed["dropped"]   被丢弃的命中
# reviewed["warnings"]  需要展示给用户的警示
# reviewed["summary"]   一句话结论
```

三种策略：

| 策略 | 行为 | 适用 |
|---|---|---|
| `flag`（默认） | 保留但标注效力，附警示 | 问答、研究 |
| `drop` | 丢弃已废止的命中只留现行有效 | 合规判断、给企业的答复 |
| `strict` | 连"效力存疑"也一并丢弃 | 需要高确定性的场合 |

同一份文件在库里可能有两份（同一份正文存成两个文件名，或根目录与栏目目录各
存一份），并列展示只是噪声。加 `--dedupe` 只留一条代表：

```bash
python force_layer.py --query "免税店的设立需要什么条件" --dedupe
```

- **只按正文合并**：逐条条文都对得上才算同一份；正文不同说明是真正不同的
  版本，两条都保留并标成 `divergent`——版本差异正是这个项目要看的东西，
  不能替使用者删掉。
- **代表用目录登记的正式名**：实测有一份正文是试行稿，根目录那份文件名却
  缺了「（试行）」，拿错名字引用会误导。
- **合并了什么会说出来**：写进返回值的 `duplicates`，命令行也一并打印。

`retrieval.py` 的展示路径默认去重；`ForceLayer.review()` 默认不去重——数据
路径宁可多给，也不替调用方丢东西。

命令行：

```bash
python force_layer.py --query "免税店的设立需要什么条件" --policy drop
```

## 两条落地路径

效力维度有两处落地，分别对应两种检索方式。

### 路径一：文本语料的推理检索

效力挂到树上以后，这条路有两种走法，协议相同、寻址不同：

| 走法 | 模型看什么 | 选址方式 | 命令 |
|---|---|---|---|
| 条文清单 | 按相关度排好的条文 | 条号（第X条） | `reasoning_retrieval.py` |
| 沿树检索 | 持久化的带效力树（章 → 条） | 节点编号（node_id） | `tree_retrieval.py` |

树的走法是这样落地的：`tree_index.py` 把正文切成 PageIndex 形状的树——节点是
`{title, node_id, start_index, end_index, nodes}`，`start_index/end_index` 是
**页码**（网页文本没有真实分页，用每 800 字一页的确定刻度），章的层级与条文
边界用的正则与检索层**同一套**。每个节点都带 `force`，所以模型看到的不是一份
判定结论，而是树上每个位置自带的效力。选中的节点按 node_id 回原文取正文。

```bash
python tree_index.py --build              # 全库建树＋效力标注（写 _force_trees.json）
python tree_index.py --doc "海南自由贸易港禁毒条例"
python tree_retrieval.py "日用消费品免税店的设立申请要提交哪些材料" --compare
```

`LocalTreeStore` 实现了与上游客户端同样的三个接缝（`get_document` / `get_tree` /
`get_ocr`），返回同一个 envelope 形状，所以 `ForceAwareClient` 包上去就能在真实
语料上跑；将来换成真实 PageIndex 索引，变的只是数据层。

`reasoning_retrieval.py` 走的是与 PageIndex 同形的推理检索：读目录、挑节点、
读正文、作答。区别在于**给模型看的目录里每个文档都带效力状态**，所以模型在
选条时就已经知道"这份已废止"，而不是系统事后拦截。

```
问题 → 召回候选文档（二元组，便宜）
     → 给模型看带效力的目录（标题＋效力，不含正文）
     → 模型选条并说明理由
     → 读取所选条文
     → 作答，每条依据标注效力状态
```

提示词里写死了两条规则：优先选现行有效的条文；只有当现行条文无法回答时，
才选已废止的并说明。实测三态表现：

| 场景 | 模型的行为 |
|---|---|
| 现行有效 | 正常引用，逐条标"现行有效" |
| 效力存疑 | 引用但标"需人工核实"，结论先提示 |
| 系列已废止 | 拒绝作为现行依据，只说明历史沿革，并指出条文不足 |

```bash
python reasoning_retrieval.py "免税店的设立需要什么条件" --show-trace
```

### 拒答分两级，不假装一个阈值能定

「这个问题语料里有没有」判不了词形。实测语料外用词形比对反而更"像":

| 问题 | 二元组在场率 | 最佳条文覆盖率 | 二元组加权覆盖 |
|---|---|---|---|
| 免税店的设立需要什么条件（语料内） | 0.64 | 0.71 | 0.34 |
| 量子计算机的制冷方案（语料外） | 0.67 | 0.67 | 0.44 |

语料外的问题三项指标都更高——因为它碰巧撞上了《保守国家秘密法》细则里
「电子计算机房」这类通用词。把阈值调到能挡住它，就会同时挡掉真问题（26 个
语料内问题里，加权覆盖最低的只有 0.22）。所以不做单一阈值，分两级：

- **召回层只做高精度粗筛**：点名了非海南辖区又没提海南的问题直接返回空
  （`scope_query()`），外加原有的词汇在场率下限。宁可漏，不可错杀。
- **完整性交给模型**：选条阶段有 `answerable` 字段，目录里没有能回答的条文
  时必须置 false，管道据此拒答并把理由带给用户。

`ask()` 的返回里带 `refusal_stage`，一眼看得出是哪一级挡下的：
`scope`（辖区粗筛）／`recall`（召回为空）／`model`（模型判定答不了）／
`select_parse`（模型没输出 JSON）／`select_empty`（选出的条号在候选里不存在）。

### 拿结果当接口用

```python
import reasoning_retrieval as rr

result = rr.ask("免税店的设立需要什么条件", DATABASE)
result["answer"]    # 回答；拒答时为 None
result["refusal"]   # 拒答理由
result["sources"]   # [{doc, article, status, doc_number}, ...]
result["forces"]    # 每份候选文件的完整效力说明
result["notes"]     # 选条时的取舍（条号重复、指名的文件不在候选里等）
```

命令行加 `--json` 拿到同一份结构，`--dry-run` 只看带效力的目录不调模型。

### 时点检索（as-of-date）

历史问题不只查“现在还有没有效”，而是把查询时点送进同一套效力推理：

```bash
python reasoning_retrieval.py "三亚市河道生态保护管理条例第一条是什么" --as-of 2023-12-31
python tree_retrieval.py "三亚市河道生态保护管理条例第一条" --as-of 2023-12-31 --dry-run
```

`temporal.py` 只使用可追溯的日期证据：

- 文头第一个日期作为文件日期；
- 紧邻“起施行／执行／生效”的日期作为明确施行日；
- 废止通知的 `effective_date` 作为废止生效日；
- 月份／年份按完整区间判断，区间跨过事件时降为“效力存疑”；
- 查询时点早于文头日期时判为尚未公布；
- 缺少明确施行日或系列版本不唯一时，不把结果升级成确定有效。

全量 1,248 份均进入正式证据索引：明确施行日 **635 份**；305 份规划、通知、
政策措施按发布日处理；剩余需施行日但缺失的 **156 份**进入人工核对队列。
每条明确日期都保存来源句、置信度和缺失项；索引带语料文件数／字节／mtime 指纹，语料
变化后不会被继续使用。

人工核对使用 `_temporal_overrides.json`：必须填写核对人、日期、官方 URL、
证据句和说明，再运行 `import_temporal_review.py` 回灌并重建索引，不改原始正文。
`audit_temporal.py` 13 项、`audit_temporal_coverage.py` 12 项离线审计共同守住日期
边界、来源追溯、政策分层和运行时降级行为。

本地兼容服务只需改成：

### 检索策略路由

同一个问题不该走同一条路：问"第X条"要精确条号，点名一份文件要看它的结构，
比较题要拉多份文档，表格型目录根本没有事项级索引。`retrieval_router.py` 先做
这个决定——**确定性、带信号、带理由**，只决定去哪儿取证据，不改变作答协议。

| 策略 | 触发条件 | 走哪条路 | 候选 |
|---|---|---|---|
| `article_exact` | 点名文件 + 第X条 | 条文索引（条号 pin） | 2 |
| `single_doc_tree` | 只点名一份**有条文结构**的文件 | 沿树检索（node_id） | 1 |
| `single_doc_flat` | 只点名一份**没有条文结构**的文件 | 句块扁平检索 | 1 |
| `multi_doc` | 比较／沿革／废止关系 | 多文档条文召回 | 4–10（自适应） |
| `default_flat` | 其余 | 条文＋段块 | 4 |
| `table_catalog` | 执法事项／指导目录类且未点名文件 | — | 拒答并说明 |
| `out_of_scope` | 非海南辖区等 | — | 拒答 |

`ask()` 按路由决定走树还是走扁平、取几份候选；**拒答在调用模型之前完成**
（`refusal_stage="route"`），不浪费一次模型调用。返回结果里带 `route` 字段，
能看到策略、信号和理由。

```bash
python retrieval_router.py "海南自由贸易港土地管理条例第三条是什么"
python retrieval_router.py "海南省消防条例和自贸港消防条例有什么区别"
```

`single_doc_flat` 这一档是实测补出来的：把"点名文件"一律送进树检索，对没有条文
结构的文档反而更差——树里只有 800 字一页、预览 34 字，而扁平路有 180 字一句的
段块，目标句看得见。

**比较题候选是自适应的**：按被比较的实体数放大（点名几份文件、或问题里写了
"五个领域""等 8 件"），"沿革／新旧／替代"再加两档，最终夹在 4–10 份。实测
"两份条例有什么区别"给 4 份，"五个领域新旧规定的沿革"给 10 份。

**表格型目录：从"只能拒答"做到"事项级索引"。** 网页正文是列式摊平的（6 万行里
只有 2 行能整行认成事项名），但页面上挂着官方 PDF 附件——改从 PDF 的**字符
坐标**还原表格：`find_tables({"vertical_strategy": "text",
"horizontal_strategy": "lines"})` 得到 6 列，再把"事项名称｜法律名称"的合并格
按**本页表头算出的分界**劈开（表头位置随章节偏移，所以逐页取）。实测能还原出
"对未经登记…的行政处罚" / "《外国企业常驻代表机构登记管理条例》"这样的干净条目。

- **2023 版：1,625 页 → 2,839 个事项**，事项名形态合格 **99%**
- 条款列可直引 **27%**：后段章节列位会偏、文本串行。这类条目不引原文，只给
  事项名与法律名，并明确提示"按官方表格原件核对"——**不把串行文本当依据**
- 路由：目录类问题 → `catalog_item`（事项级检索），来源带效力状态；
  事项索引无匹配 → `catalog_empty` 拒答
- 防住的旧隐患：点名目录时曾会把 7,016 条"条款引用"当条文灌进候选，现在注入
  前先过结构判据

```bash
python catalog_index.py --build --only 2023   # 下载官方 PDF 附件并解析（约 2.5 分钟）
python audit_catalog.py                       # 7 项：形态、检索、效力、串行条款、路由
```

### 路径二：PageIndex 客户端（PDF）

走真实 PageIndex 客户端时，工具层读文档只经过三个方法：`get_tree`（目录）、
`get_ocr(format="page")`（正文）、`get_document`（元数据）。包住这三个，
agent 看到的每个工具结果就都带效力了。

```python
from pageindex import PageIndexClient
from pageindex_force_adapter import ForceAwareClient, force_instructions

client = ForceAwareClient(PageIndexClient(index=..., chat=...), DATABASE)
tools = client.as_openai_tools()      # 工具结果自动带 force
instructions = force_instructions()   # 追加到 agent 的系统提示
```

`force_instructions()` 告诉模型怎么用这个字段：优先引用现行有效的；只有现行
条文答不了才引已废止的并明示失效；存疑的要标注核实。注入层级覆盖文档级、
节点级、页面级三处。

### 用真实索引验证，而不是假客户端

上面那段接缝过去只用假客户端验过——接线对，不代表真跑得通。现在有真实索引的
验证路径：

```bash
python build_pi_store.py --pdf-only      # 三份已知效力的文档 → 中文 PDF
python build_pi_store.py --build         # 用真实 PageIndexLocalClient 建索引
python pageindex_force_adapter.py --real # 验证 get_tree 返回的节点确实带 force
```

样例是现行有效／效力存疑／系列已废止各一份。索引由上游自己建（PDF 入库、
节点由上游布局分析产出），这里只包住它的三个读文档方法。实测结果：

| 文档（文号＝主键） | 预期效力 | 上游树 | 带 force | 结论 |
|---|---|---|---|---|
| 《海南自由贸易港建设投资基金管理办法》琼府办〔2021〕71号 | 系列已废止 | 45 节点／6 章／深 2 层 | 45/45 | 一致 |
| 《海南省关于在琼台湾同胞待遇的若干规定》海南省人民政府令第80号 | 效力存疑 | 11 节点 | 11/11 | 一致 |
| 《海南自由贸易港商事调解组织登记管理办法》海南省人民政府令第329号 | 现行有效 | 24 节点 | 24/24 | 一致 |

**为什么用文号做主键。** 标题会被"（试行）"、书名号、文件名截断搅乱——库里那
份免税店办法的正文是试行稿、文件名却缺了"（试行）"，同一份文件还有两个副本。
文号不会：manifest（`_pi_manifest.json`）以文号为键，把"带版式 PDF"和"效力
记录"缝在一起，运行时也是从 PDF 正文里读文号来定位效力，而不是拿文件名猜。
`real_selftest` 会核对 manifest 键与正文读到的文号是否一致。

manifest 里的**效力记录由 `ForceLayer` 现算**，不是写死的预期值——写死的等于
开第二个真值来源，判定一改它就悄悄过期（`spine_check.py` 第 6 项专门守这条：
逐条重算比对，并报三态覆盖还成不成立）。样例里第二项 `sampled_for` 只是"挑它
来覆盖哪一态"的选题意图，与现算不符会如实报出来，而不是拿意图当结论。

**为什么是一页一条。** 上游的 optimize 先合并"同页兄弟"，再按"折叠后要扫的
页数是否比走树更省"决定折叠子树（`merge iff S(v) <= tree_cost(v)`）。条与章
挤在同一页时兄弟全被并掉，层级就没了；一条一页时 `tree_cost = 1 + 1 = 2`，
远小于章的页数，层级保得住。纯版式（不写书签）只切出一层——中文编号"第一章"
不在上游的编号识别里（它只认数字与字母），所以层级靠**书签 + 版式**一起给。

这条检查先后抓到两个真 bug：

1. **客户端返回的文档名带 `.pdf` 后缀**，而效力层按标题查库。不处理后缀就查不
   到正文，存疑规则拿不到文头年份，《海南省关于在琼台湾同胞待遇的若干规定》
   被误报成"现行有效"——"只给标题会误判"那个坑换了个入口又踩一次。
   `ForceAwareClient._title()` 现在统一去后缀。
2. **`own_numbers()` 认不出折行的文号。** PDF 里"海南省人民 / 政府令第329号"
   被折成两行，正则接不住，于是文号读成空、主键退化成标题。现在先压平空白再
   匹配（全库 814 份的状态分布不变，只是折行的情况不再漏）。

当前解释器缺 PyPDF2／litellm 时，检查会自动改用项目 venv 跑（`PageIndex\.venv`）；
venv 也不可用时就诚实跳过并说明原因，不会假装通过。

`audit_tree_force.py` 里有两项走真实索引：第 8 项验"上游树节点带 force"，
第 9 项专验**嵌套节点也带 force**（含子节点的那些节点），并报出每份树的层级
形状。样例里只有带章的《建设投资基金管理办法》有嵌套，另两份源文档本来没有
章——这种情况第 9 项会如实说明，不假装验过。

两种路径共用同一个 `ForceLayer`，所以判定结果一致。

## 三态判定

判定刻意不做成二值，因为政策文件有三种真实状态：

| 状态 | 含义 | 处理建议 |
|---|---|---|
| 现行有效 | 本库未见废止依据 | 可以引用 |
| 效力存疑 | 年代久远、文头无修订记录、也无废止依据 | 需人工核实 |
| 已废止 | 有明确废止依据（通知或文件内条款） | 不可作为现行依据 |

"存疑"不等于"已废止"，也不等于"有效"。系统宁可说不知道，也不给一个自信
的错误结论——这在政策场景里比准确率本身更重要。

## 判定携带的信息

任何一个判定都不是一个状态词，而是一份可核验的说明。"效力存疑"最容易变成
一句没用的"不确定"，所以它必须说清原因、缺什么、下一步做什么：

```json
{
  "status": "效力存疑",
  "confidence": "medium",
  "reason": {
    "code": "questionable",
    "text": "1995 年公布（距今约 31 年），文头无任何修订记录，本库已索引的
             废止依据中也未点名——这类老规章更常见的情形是被后续文件替代
             而非明文废止"
  },
  "checked": {"废止通知": 23, "文件内废止条款": 24, "点名文件数": 57},
  "missing": ["未见该文件被明文废止的依据", "未见后续修订版本或替代文件",
              "本库未覆盖全部政策文件，也未见国家级法律与其他省级栏目"],
  "next_steps": ["查该主题是否已有新版规章或替代文件",
                 "查国家法律法规数据库（flk.npc.gov.cn）确认效力状态",
                 "向发布机关或业务主管部门确认"],
  "evidence": {"note": "无废止依据，也无修订记录", "year": 1995},
  "caveats": ["在核实之前不应作为现行依据；如被替代，其条文可能已被改写"]
}
```

字段含义：

| 字段 | 用途 |
|---|---|
| `reason` | 为什么是这个判定，一句话可读 |
| `checked` | 我们查了多少（废止通知、文件内条款、点名文件数），界定结论范围 |
| `missing` | 缺哪一条证据才能给确定结论 |
| `next_steps` | 使用者接下来该做什么 |
| `evidence` | 结构化依据（文号、年份、依据文件、链接） |
| `caveats` | 使用该条文时的注意事项 |

已废止（`repealed`）与系列已废止（`series_repealed`）用同一套结构，只是
`reason` 指向明确依据、`missing` 通常只剩覆盖率那一条。

## 判定依据从哪来

两个来源，缺一不可：

1. **专门的废止决定/通知**——标题含"废止"的独立文件（23 份）
2. **文件正文里的"同时废止"条款**——新条例的附则常写"本条例自 X 日起施行。
   《旧条例》同时废止"（24 条）。**只扫标题会整类漏掉**，所以每份文件被
   取用时都会顺带扫一遍，索引随使用自动增长。

## 注意事项

**调用判定函数必须把正文一并传入。** 三态里的"效力存疑"依赖正文开头的年份
与修订记录；只给文档名会让这条规则失效，于是一份存疑文件被报成"现行有效"。
这个错误在检索层、推理层、客户端适配器里各出现过一次。

现在 `ForceLayer.status_for()` 在只收到标题时会自己去库里找对应文件并读正文，
所以即便调用方忘了传也不会错。新增调用点时仍然建议显式传入 `text`——库里
没有该文件时，自查找不到就只能退化为"未见废止依据"。

**工具类文件的识别要覆盖无书名号的写法。** "关于废止海南经济特区农药批发
零售经营许可管理办法的决定"这类标题里没有《》，早期规则漏判，导致它被当成
被废止对象。现在统一用 `warn.is_instrument()` 判断，`warn` 与 `selfcheck`
共用同一个正则。

**书名号里的是被废止的对象，还是废止它的依据？** 废止决定常把两者写在同一句：

> 为贯彻落实《海南自由贸易港公平竞争条例》以及 2023 年 10 月 1 日起施行的
> 《海南经济特区农药管理若干规定》有关规定，省人民政府决定废止《海南经济
> 特区农药批发零售经营许可管理办法》。

早期解析器只看书名号前后 90 字里有没有"废止"二字，于是把前两个依据书也当成
被废止对象，《海南自由贸易港公平竞争条例》因此被误判成"已废止"。现在按动词
管辖判断：`repeal.governed_by_repeal()`（通知）与 `embedded_repeals.scan_text()`
（文件内条款）都要求书名号处在废止动词的辖域内——动词之后 60 字内，或紧邻动词
之前只隔文号、日期。同一套判断还要跳过书名号内部的"废止"（《国务院关于废止和
修改部分行政法规的决定》是文件名，不是动词），以及"…的修改决定"里被修改的对象。

这次修正的效果有据可查：`audit_repeal_targets.py` 重抓 24 份通知逐条对比，
修正 5 处名单（4 处误判移除、1 处真目标补回），全库状态只有一份文件变化——
《海南自由贸易港公平竞争条例》从"已废止"回到"现行有效"。

**条文边界要靠两道约束，不能只认"第X条"这一种写法。** 树审计要求"树上的条文
与检索层逐字一致"，一比就发现检索层有三份文件对不上，根因是两个：

1. **章标题不是边界**——`parse_articles` 遇到"第三章…"不关闭上一条，于是章下的
   内容全被上一条吞掉（正文里这类位置有 168 处，真正造成吞并的是下面第 2 条
   那种认不出条号的地方）。
2. **条号有抽取瑕疵**——"第十**—**条"（破折号顶替了"一"）、"第三十五 条"
   （数字与"条"之间有空格）。正则认不出，这一条就成了上一条的续行。

现在 `retrieval.article_name()` 统一归一见到的条号（"第十—条"规范成"第十一条"），
章标题也关掉当前条文；树与检索层共用这一个函数，所以两边不可能再分叉。修完
条文数 2839 → 2842，`audit_tree_force.py` 的逐字比对 814 份全过。

**正文不要用 `<meta Description>`。** 抽取器一度是"Description 优先"——而网站
把 Description 写成新闻导语或公告文头，一百多字就"够长"，于是入库闸门
（`MIN_CHARS = 120`）放行，**812 份里有 603 份存的是摘要不是正文**。实测同一
页面：`<p>` 段落 4847 字、Description 122 字；抽查 20 份重抓，去空白字数中位
从 132 涨到 4628。

现在改成**段落优先、Description 兜底**（`repeal.body_text_with_source()` 会
返回来源标记），并用 `refresh_bodies.py` 按 manifest 里记录的 URL 重刷已有正文
（覆盖前镜像备份到 `_library_backup/`）。语料因此长了一大截：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 正文份数 | 812 | **1244** |
| 去空白字数（中位／总计） | 204／15.7 万 | **4458／884 万** |
| ≥500 字的文档 | 112 | **1169** |
| 有条文结构的文档 | 133 | **654** |
| 文件内"同时废止"条款 | 25 | **159 份** |
| 三态里的已废止／系列已废止 | 4／4 | **55／12** |
| 带效力树的节点／条文 | 3808／2842 | **33665／24387** |

目录（1872 条）里的水分也要挤掉才算得出覆盖率：**594 条标题重复、15 条抓取噪声**
（`.&nbsp;省工业和信息化厅` 这种）、**8 条栏目列表页**（`list.shtml`，标题就是厅名）
——真实文档约 1,255 份，现在盘上 1,244 份，**覆盖率约 99%**，只剩 11 份本身过短。

抽取规则后来又补了两层，因为剩下的薄文档分两类：**正文在无 class 的 `<div>` 里**
（一页拆成好几段，`<p>` 阶段取不到）和**正文在附件里**（规划、方案、决定常挂
PDF/Word）。现在的取法是：段落 vs 容器块取更长者 → 附件（PDF 用 `pypdf`、DOCX
直接解 `word/document.xml`）→ Description 兜底。老式 `.doc` 读不了，如实标注。

**表格型文档不能当法规入库。** 补全正文后条文数从 14,274 跳到 32,109，涨幅远超
新增文档数——查到根因是两份《综合行政执法事项指导目录》（1.7M／1.68M 字）：那是
表格，每行开头就是它引用的条款（"第三十五条第一款 …"），同一句在不同条目里重复
上千次。两条修法：

- **行级去重**（`repeal.dedupe_lines`）：同一句只留一次，两份目录 1.68M → 1.10M 字。
- **条号单调性判据**（`retrieval.looks_like_articles`）：真法规的条号基本递增（实测
  ≥0.91），表格目录乱跳（0.56／0.57）。不达标的文档**不进条文索引**，但正文仍以
  页节点入树，一个字不丢。

修完条文数回到 **14,582**，条文索引里最大的文档只有 309 条（此前是 9,092）。

**正文里的简称不是文件名。** 有份实施意见写"（以下简称《条例》）"，扫描器就把
**"条例"**当成了一个被废止的文件名；而匹配规则是 `n in title`，于是**每一份标题
含"条例"的文档都被判成已废止**——实测把 237 份误判（真实值 58）。现在有一道名称
闸门（`warn.is_usable_name`）：太短或只有文书类型（条例／办法／规定／通知…）的
一律不用来匹配。

**"标题互相包含"会把版本差异算成废止。** 宽松匹配下，"2010 年版《洋浦经济开发区
条例》废止了 1992 年《**海南省**洋浦经济开发区条例》"和"正式版废止《…条例（试行）》"
都会被算成"本库这份已废止"。现在按匹配强度分档（`warn.name_strength`）：

| 强度 | 含义 | 判成 |
|---|---|---|
| `exact` | 两边完全相同 | 已废止 |
| `contained` | 名字被文件标题包着（"…关于印发《X》的通知"） | 已废止 |
| `version` | 只差"（试行）"这类版本标记 | 系列已废止＋请核对版本 |
| `superset` | 我们的标题只是名字的一部分（对方多了"海南省"前缀） | 系列已废止＋请核对版本 |

只有前两档够格判"已废止"——分不清本库这份是要废止的那一版还是新的一版时，
宁可说"同系列，请核对"，也不硬判。

已废止从 4 涨到 24 不是判定变严，而是**正文补全后隐藏的"同时废止"条款露出来了**
——旧的短正文里根本没有附则。顺带发现 `_library_manifest.json` 不能当账本：它
记着 1110 份"已存"，其中 462 份文件不在盘上，盘上另有 164 份它没记（抓取工具每
轮重写它）。重刷工具因此改成**以盘上文件为准、URL 从目录 join**。

### 条文级部分废止

文档整体现行有效，不代表其中每一条仍然有效。`article_force.py` 单独处理修改决定
造成的条文变化：

- `删去第X条` → `条文已废止`；
- `删去第X条第Y款/项` → `条文部分失效`；
- 修改决定跨过查询时点、日期未知或条文重新编号 → 降为存疑或保持文档级状态；
- 已吸收修改并重新公布的文本不套用旧条号。

当前索引识别 60 个事件、35 份修改决定、57 份目标文档、313 个条文目标；
`audit_article_force.py` 28 项全过。可用：

```bash
python build_article_force_index.py
python audit_article_force.py
```

`reasoning_retrieval`、`tree_retrieval` 和 `pageindex_force_adapter` 都会消费同一个
`ForceLayer.article_status_for()`；索引带语料指纹，语料变化后自动拒用旧索引。

### validity-QA 评测

分类指标（三态判定对没对）不等于问答指标。`eval_set.json` 保留 v2 的 30 道
基础题，`eval_set_v3_additions.json` 独立保存新增 50 题；加载时通过 `extends`
合并成 80 道端到端题。每题带人工读条文写下的真值：`must_cite`（答案必须引到
的条文）、`key_points`（答案必须出现的要点）、`type`（该题的正确行为）。
模型回答单独写到 `eval_results_v3.json`，与题集和项目进度文档分离。

| 类型 | 题数 | 正确行为 |
|---|---|---|
| `in_force` | 47 | 必须作答，且引用的条文都是现行有效 |
| `trap` | 20 | 涉及已废止文件：拒答，或引用但明确标注失效 |
| `off_corpus` | 6 | 必须拒答 |
| `questionable` | 7 | 可引用，但必须提示人工核实 |

评分分三条，互不掩盖：答案对（必备证据＋要点齐）、引用合规（没有未标注的
失效引用）、现行有效题只引现行有效条文。当前成绩 **80/80**：答案对 54/54、
现行有效题 47/47、陷阱题 20/20、存疑题 7/7、语料外 6/6、引用合规 80/80。

**v2 的两处改动值得记下来。** 一是**删掉了两道前提已变的题**：种子进出口许可、
重点项目建设保障措施原来被当成"已废止的旧版"，语料补全并修掉自指误判后，发现
库内那份其实是**修订后的新版**（正文废止的是上一版），判定已纠正为现行有效。
二是新增两类题：

- **新版不得误判**（eq-11 政府质量奖、eq-12 游艇办法）：这两份文件的正文都写着
  "…旧的同名文件同时废止"，如果判定层把"自己"算进去，就会把现行新版判死。
- **同名新旧版的陷阱**（trap-05…09）：土地管理、旅游、城乡规划、消防、养犬——
  库里同时有**已废止的旧版**和**现行新版**，问法贴近旧版，考的是别把旧版当现行用。

`--selftest` 用构造答案验证评分器本身（10 项，离线）：漏引证据、答漏要点、
该拒未拒、不该拒却拒、把失效条文当现行依据、存疑未提示核实，都在覆盖内。
`--validate-data` 是第二道离线闸门：逐条检查题号/题面唯一、`must_cite` 指向的
条文真实存在、题型与当前效力一致，以及每道陷阱题确实点名了已知失效文件。

```bash
python eval_qa.py --validate-data       # 只校验测试数据，不调模型
python eval_qa.py --run                 # 跑完整 80 题并写专属结果文件
python eval_qa.py --run --only eq-38    # 只重跑一题并更新缓存
python eval_qa.py                       # 用缓存离线复评
```

## 已知边界

- **条文级状态只覆盖删除事件**：整条删除和只删款/项已经进入索引；“将第X条修改为…”
  目前仍按文档级有效处理，要逐字核查新旧文本需再建条文差异索引。
- **检索单元覆盖**：条文（第X条）之外，没有条文结构的文档现在按**句切块**入库
  （`retrieval.block_units`，约 180 字一块），所以 1,244 份正文都能被检索到
  （此前只有 654 份有条文的能被检索，其余 592 份即使拿正文原句查也是 0 命中）。
  块上限不能调大：目录里只给模型看块的开头，块太长会把"到2030年…目标"这类
  关键句埋进中间，实测模型因此拒答。
- **覆盖率**：目录 1872 条挤掉水分后约 1,255 份真实文档，已抓 **1,244 份（99%）**；
  仍有 11 份本身过短无法入库。即便如此，"现行有效"的置信度仍多为 low——本库
  未见废止依据，不等于确认有效。
- **正文在附件里**：有类页面只有通知抬头，正文（规划、方案）挂在附件。现在会
  自动跟一层附件：PDF 用 `pypdf`、DOCX 直接解 `word/document.xml`。**老式
  `.doc`（二进制复合文档）读不了**，这类只能人工另找出处；另有极少数文档本身
  就是一两句话（通告、废止决定），短是正常的。
- **失效方式**：被上位法取代、有效期届满、附件里的清理清单，这三类依据
  不在已爬语料中，是"效力存疑"的主要来源（24 份）。
- **索引已持久化**：`_retrieval_index.pkl`（约 41 MB）带语料指纹，语料一变自动
  重建。冷启动读盘 **5.6s → 0.68s**，同一进程连续提问走内存缓存（0.16s）。
  现场重建仍要 ~6.5s，所以批量改完语料记得先跑一次查询把索引烘出来。
- **繁简已通**：查询侧用 zhconv 归简（装在 `haikou/_vendor`，不污染共享运行时），
  繁体「遊艇碼頭建設程序」能命中同一份文件。缺 `_vendor` 时退化为原样，不假装
  支持；重装：`pip install --target haikou/_vendor zhconv`。
- **模型调用有重试**：Provider 对网络错误、429／5xx 统一退避重试；认证错误立即失败。
  最终失败返回 `refusal_stage="llm_error"`，不泄露密钥，也不让一次网络抖动把整轮
  评测打崩。
- **时点日期覆盖**：明确施行日 635/1,248，政策发布型 305；仍需人工核对施行日的
  156 份已进入 `temporal_review_v1/review_queue.csv`。系统不会把“公布了但没识别到
  施行日”当成有效；月／年区间跨过事件时也降为存疑。
- **语料外主题靠模型兜底**：粗筛只拦得住"点名了别处"这一类。像「个人所得
  税专项附加扣除标准」这种用海南邻近词汇、实为国家级政策的提问会被放行，
  由选条阶段的 `answerable` 判断挡下。这一级是模型判断，不是确定性规则。
