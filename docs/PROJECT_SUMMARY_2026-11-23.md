# 海南政策效力感知问答项目说明

日期：2026-11-23

> **目标更新（2026-11-23）**：项目最终目标已调整为申请软件著作权。本文保留
> 原商业价值和技术验证结论，用来界定作品边界与已知限制，但不再把“能否胜过
> 联网模型”作为项目是否继续或能否申报软著的前置条件。具体申请计划见
> [`SOFTWARE_COPYRIGHT_APPLICATION_PLAN.md`](SOFTWARE_COPYRIGHT_APPLICATION_PLAN.md)。

## 一、项目最初目标

本项目尝试在 PageIndex 和本地政策语料之上，构建“法律效力感知”的政策问答与
比对系统。目标不是普通政策检索，而是让以下信息进入检索、选条和回答过程：

- 文件当前是否有效；
- 文件在某个历史时点是否有效；
- 文件是否被新文件废止或替代；
- 条文是整条废止还是部分失效；
- 每个结论能否追溯到文件、条号、生效日期和官方依据。

一句话概括：

> 在回答政策问题前，先判断所引用政策现在或某个历史时点是否仍然算数。

## 二、当前结论

项目已经形成可运行的工程原型，但**尚未证明具有足够的产品差异化**。

主要原因：

1. 普通政策问答、材料清单、申请流程等内容，带联网搜索的通用模型已经可以高质量
   完成；
2. 明确要求“先核验现行有效、废止依据、替代文件和生效日期”后，联网模型可以
   完成基本的版本检查；
3. 当前系统虽然保存了结构化效力数据，但回答模型仍可能在 `trap-05`、`trap-07`
   中把旧条例或旧条例的修改决定当作现行依据；
4. 项目尚无真实用户、独立专家盲评和客户付费验证，因此不能证明比通用联网助手
   更有业务价值。

更准确的定位是：

> 一个工程完成度较高、可用于研究和演示的效力感知 RAG 原型，不是已在真实法律
> 或政策业务中得到验证的产品。

## 三、已经完成的主要内容

### 1. 本地政策库与检索

- 约 1,248 份海南政策正文；
- 约 43,642 个条文与段块检索单元；
- 条文级二元组倒排索引；
- 无条文文档的句块检索；
- 题名直查、繁简归一和持久化索引；
- 七类检索路由；
- 带效力的章、条、页节点树。

### 2. 文档效力与历史时点

- 现行有效、效力存疑、已废止、系列已废止；
- 废止通知与正文“同时废止”条款两类依据；
- 公布日、施行日、废止日和查询时点；
- 缺少证据时降为存疑，不把“没找到废止依据”升级为“确定有效”；
- 历史时点不污染当前效力缓存。

### 3. 条文级部分失效

- 从修改决定中识别“删去/删除第X条”；
- 识别删除款、项导致的“条文部分失效”；
- 检索、选条、树节点和 PageIndex 适配器使用同一套条文状态；
- 修改决定跨查询时点时降为存疑。

### 4. 评测与测试基础设施

- v2 基础题、v3 增补题和 v4 路由覆盖题；
- 当前共 84 道端到端题；
- 覆盖精确条号、多文档、事项目录、历史时点、已废止陷阱、存疑和语料外问题；
- 答案必须匹配 `must_cite`、`key_points` 和引用效力；
- 评分器覆盖遗漏证据、错误拒答、`llm_error`、否定句和部分失效；
- 每题结果保存模型、题集、代码、语料指纹和生成时间；
- 默认拒绝缺元数据或指纹不一致的旧结果；
- 测试运行器保存命令、耗时、退出码、stdout/stderr 和环境信息；
- 历史测试资料统一归档到 `test_runs/legacy-archive/`。

### 5. Web 服务

- 本机 Web 页面与异步 JSON API；
- 政策提问、历史时点、效力状态、拒答原因和引用来源展示；
- 请求体限制、输入校验、错误脱敏和安全响应头；
- Web 服务审计 22/22。

## 四、关键实测发现

### 1. 联网搜索不等于版本核验

普通联网模型在以下两题中检索到了旧条例和修改决定，但没有说明旧条例已废止：

- 《海南经济特区土地管理条例》；
- 《海南省城乡规划条例》。

问题不在于模型找不到网页，而在于默认提问只要求“解释这条规定”，没有要求它
反向检查是否存在更新版本、废止关系或替代文件。

### 2. 明确提示后，联网模型可以完成版本核验

把问题改为：

> 先核验旧条例是否仍然有效，是否已被新文件废止或取代；列出废止依据、替代文件
> 和生效日期；若已废止，不得继续作为现行依据。

同一联网模型正确指出：

- 《海南经济特区土地管理条例》于 2023-05-01 废止；
- 替代文件为《海南自由贸易港土地管理条例》。

因此，“模型不会版本核验”这一产品假设并不完全成立。

### 3. 当前系统也没有真正解决旧法问题

严格复评后，当前系统有两个真实陷阱题失败：

- `trap-05`：旧《海南经济特区土地管理条例》；
- `trap-07`：旧《海南省城乡规划条例》。

此前 84/84 包含评分器误把“未发现/未出现已废止”“无需提示失效”当成失效警告
的假通过。修正后为 **82/84**。

### 4. 联网模型的具体法条仍可能来自草案

明确提示后的联网模型虽然正确识别了旧法废止，但部分现行条例细节来自草案征求
意见稿。它自己提示“最终文本可能调整”，因此：

- 效力判断可以通过；
- 具体条文内容仍不能直接视为最终法律文本；
- 搜索质量、来源等级和正式文本确认仍是独立问题。

## 五、当前问题

### 产品与差异化

- 通用联网模型可以完成许多普通政策问答；
- 明确提示后也能完成基本废止与替代核验；
- 当前系统没有证明比联网模型更准确；
- 没有真实用户和付费场景；
- 没有独立法律或政策专业人员盲评；
- 没有专有数据、线下渠道或客户工作流。

### 数据与回答

- 文号已在冻结前首轮清理：733/1,248 可提取，515 份进入逐条人工补证；
- 明确施行日已提升到 752/1,248，剩余 83 份保守降为存疑；
- 2022／2023／2024 三版事项目录共 11,602 条，各版条款直引率均为 100%；
- 条文“修改为”的新旧文本差异尚未补全；
- 部分同名版本仍需要人工确认；
- 回答模型可能忽略已知效力数据，继续引用旧条例或其修改决定。

### 测试与验证

- 84 题仍是内部测试集；
- v3 A/B 来自同一所有者转录，不是独立盲评；
- v4 新增 4 题尚未盲评；
- 直接模型基线没有联网搜索；
- 联网模型目前只做了少量人工对照，不是完整统计样本。

## 六、仍然可保留的价值

即使停止产品化，也不是所有投入都归零。

### 可迁移资产

- 对 RAG、检索索引、树结构和评测工程的理解；
- 政策版本、废止关系、历史时点和条文级部分失效的数据模型；
- 测试批次、结果指纹、失败归因和反例库；
- “联网搜索不等于法律版本核验”的实测结论；
- 普通 RAG、直接模型和效力系统的对照数据；
- 可运行的本地 Web 原型和完整工程文档；
- 可用于作品集、项目答辩、研究或求职展示的案例。

### 可恢复的投入

可以把现有工作整理为：

1. 一个“法律效力感知 RAG”工程案例；
2. 一份“联网搜索与法规版本核验”对比报告；
3. 一个离线政策库审计原型；
4. 一个政策版本变更扫描和数据治理原型。

## 七、是否继续

不建议因为过去已经投入很多而继续扩大项目。沉没成本不应成为继续投入的理由。

### 应当停止扩展的情况

- 找不到真实用户；
- 用户只需要一次性政策问答；
- 用户可以直接使用联网助手；
- 没有私有语料或离线要求；
- 不能获得专业人员的独立核验；
- 再投入一个月也无法形成明确交付。

以上任意多项成立时，应停止产品化开发，保留项目作为研究或作品集。

### 值得继续的情况

只有同时具备以下条件才值得继续：

1. 有明确客户或内部使用场景；
2. 客户有大量私有政策、制度或历史文件；
3. 必须离线运行或数据不能离开内网；
4. 需要持续监控更新，而不是一次问答；
5. 需要批量、可复现、可审计的检查；
6. 有专业人员能确认版本关系和最终文本；
7. 可量化减少人工时间或错误率。

如果这些条件不能成立，继续做通用政策问答的商业价值很低。

## 八、建议的收尾方案

### 方案 A：冻结并打包

适合没有明确客户的情况。

1. 冻结新功能；
2. 提交当前代码快照；
3. 保留测试数据、对照实验和失败案例；
4. 完成 README、演示和项目总结；
5. 将项目定位为工程/研究案例，不再宣称可替代法律核验。

### 方案 B：转向离线合规审计

适合有企业或机关内部文件的情况。

核心产品不是聊天，而是：

- 批量导入内部制度、答复、报告；
- 检查引用政策是否失效；
- 标出替代文件和历史版本；
- 生成带证据和审核人的审计报告。

### 方案 C：转向政策更新监控

适合有明确关注领域和持续更新需求的情况。

核心产品是：

- 每日/每周扫描官方栏目；
- 发现新增、修改、废止和替换；
- 生成待审核变更清单；
- 审核后发布并通知相关人员。

## 九、最终判断

这个项目不是“完全没有意义”，但也不是当前就应该继续投入的商业产品。

最合理的总结是：

> 项目已经证明了政策效力感知在工程上可以实现，也暴露了普通联网搜索在版本核验
> 上的默认缺陷；但在明确提示后，通用联网模型同样能够完成核验，因此“会判断政策
> 是否有效”本身不构成可持续壁垒。

如果没有私有数据、离线要求、持续监控或明确客户，建议停止产品化扩张，将现有
成果整理为研究/工程项目后收尾。继续投入前，应先验证真实用户是否愿意为“可审计、
可批量、可离线、可持续更新”的治理能力付费，而不是为普通政策聊天付费。
